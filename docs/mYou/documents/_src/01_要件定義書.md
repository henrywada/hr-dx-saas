## 1. はじめに

### 1.1 本書の目的

本書は、ミュー株式会社（以下「甲」という）向けに構築した **製品トレーサビリティ・有効期限管理システム**（HR-DX SaaS の製品トレーサビリティ機能。以下「本システム」という）について、甲の業務要求とシステム化要件を定義したものである。

本システムは、スプレー缶製品「セルフィール MS」を **製造ロット単位** で管理し、製造元からの入荷から施工会社への出荷、さらに有効期限の監視・通知までを一貫してデジタルに記録・照会することを目的とする。

### 1.2 適用範囲

本書が対象とする範囲は次のとおりである。

| 区分         | 範囲                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------- |
| 対象業務     | 入荷（仕入）、在庫管理、出荷（納品）、トレース照会、有効期限監視・通知、納入先マスタ保守 |
| 対象製品     | セルフィール MS（スプレー缶）                                                            |
| 対象利用者   | 甲の入荷・出荷・照会・アラート担当者、および甲のシステム管理担当者                       |
| 対象システム | HR-DX SaaS（マルチテナント SaaS）上に構築された甲専用テナントの製品トレーサビリティ機能  |
| 対象外       | 製造会社の生産管理、施工会社側の在庫管理、甲の会計・購買・売掛システム                   |

### 1.4 用語定義

| 用語                             | 定義                                                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------- |
| ロット                           | 製造単位。物理的には製品が梱包された段ボール1箱に相当し、1ロットに複数本のスプレー缶が含まれる |
| ロット番号                       | ロットを一意に識別する番号。書式は `LOT-YYYYMMDD-NNNN`                                         |
| ロットQR                         | 段ボール（ロット）に貼付する QR コード。ロット番号・製造日・有効期限を保持する                 |
| トレーサビリティQR（トレースQR） | 施工会社へ出荷する際に発行・貼付する QR コード。読み取ると製品情報の公開ページが開く           |
| TraceNo                          | トレーサビリティQR の発行単位を一意に識別する番号。書式は `YYYYMMDD-NNNN`                      |
| 施工会社（納入先）               | 甲が製品を出荷する取引先。本システムでは納入先マスタとして管理する                             |
| 出荷先No（得意先No）             | 施工会社ごとにテナント内で採番される連番                                                       |
| 残数                             | ロットの在庫として残っている本数（`quantity_remaining`）                                       |
| 使用数                           | 出荷済み製品のうち、施工会社での使用が確認された本数                                           |
| 処理ステータス                   | トレーサビリティQR 発行分に対する管理区分（未使用／使用済／アラート無視）                      |
| テナント                         | マルチテナント SaaS における契約企業単位のデータ区画。甲は専用テナントを保有する               |
| RLS                              | Row Level Security。データベースの行単位アクセス制御機構                                       |

## 2. 現状業務と課題

### 2.1 現状（システム導入前）の業務

1. 製造会社が「セルフィール MS」を製造し、甲へ納品する
2. 甲は納品された製品を倉庫に保管する
3. 施工会社から受注が入ると、甲は在庫から製品を取り出して出荷する
4. 施工会社は現場で製品を使用する

### 2.2 課題

| No   | 課題                                                                 | 影響                                       |
| ---- | -------------------------------------------------------------------- | ------------------------------------------ |
| C-01 | 出荷した製品が「いつ・どの施工会社へ」渡ったかを追跡する仕組みがない | 品質トラブル発生時に回収範囲を特定できない |
| C-02 | 有効期限の管理が担当者の記憶・紙台帳に依存している                   | 期限切れ製品が現場で使用されるリスクがある |
| C-03 | 在庫の残数がリアルタイムに把握できない                               | 発注・引当の判断が属人的になる             |
| C-04 | 施工会社へ期限接近を知らせる手段がない                               | 期限切れによる廃棄ロスが発生する           |
| C-05 | 製品の正規流通経路を証明する手段がない                               | 転売・不正流通の抑止力がない               |

## 3. システム化の目的と効果

### 3.1 目的

| No   | 目的                                                                     | 対応する課題 |
| ---- | ------------------------------------------------------------------------ | ------------ |
| G-01 | 製造ロット単位で流通履歴を記録し、いつでも照会できるようにする           | C-01, C-05   |
| G-02 | 有効期限をシステムで一元管理し、期限接近を可視化する                     | C-02         |
| G-03 | 在庫の残数を数量ベースでリアルタイムに把握できるようにする               | C-03         |
| G-04 | 期限接近を施工会社へ通知する手段を提供する                               | C-04         |
| G-05 | 出荷ごとに固有の QR を発行し、製品の正規性を第三者が確認できるようにする | C-05         |

### 3.2 導入効果

- **品質管理の強化** — 有効期限が近い製品を把握し、古い製品の使用を未然に防ぐ
- **トレーサビリティの確保** — 各ロットが「いつ・どの施工会社へ・何本」出荷されたかを追跡でき、品質トラブル時の回収範囲をロット単位で即座に特定できる
- **不正流通の抑止** — 出荷単位で固有の QR を発行することにより、正規ルートで納入された製品であることを確認できる
- **作業効率の向上** — 段ボール1箱に対して QR は1枚。缶を1本ずつスキャンする必要がない

## 4. 関係者と役割

| 関係者                 | 役割                                         | 本システムの利用                                                        |
| ---------------------- | -------------------------------------------- | ----------------------------------------------------------------------- |
| 製造会社               | 製造、ロットQRラベルの貼付、甲への納品       | 原則としてシステム外。ラベルは甲が定めた書式に従う                      |
| ミュー株式会社（甲）   | 入荷・在庫・出荷・照会・アラート・マスタ保守 | **本システムの主たる利用者**                                            |
| 施工会社               | 発注、製品の受領、現場での使用               | 直接操作しない。アラートメールの受信、トレーサビリティQR の読み取りのみ |
| 一般消費者・現場作業者 | 製品の使用                                   | トレーサビリティQR をスマートフォンで読み取り、公開ページを閲覧する     |

### 4.1 利用者区分と権限

本システムは HR-DX SaaS の権限モデル（`app_role`）に従う。

| 利用者区分               | 権限                           | 利用可能な機能                                                 |
| ------------------------ | ------------------------------ | -------------------------------------------------------------- |
| 一般利用者（現場担当者） | テナントユーザ                 | 入荷登録、在庫一覧、出荷登録、出荷リスト、トレーサビリティ検索 |
| 管理担当者               | テナントユーザ／テナント管理者 | 上記に加え、納入先マスタ保守、有効期限監視・アラート送信       |
| システム管理者           | テナント管理者                 | 上記に加え、利用者アカウント管理、役割ごとの機能割当           |

> 本システムの各画面は HR-DX SaaS の「製品トレーサビリティ」サービスカテゴリに属し、テナント契約（`tenant_service`）と役割割当（`app_role_service`）の**両方**で許可された利用者にのみ表示される。

## 5. 業務フロー要件

### 5.1 全体業務フロー（To-Be）

```
[製造会社]
  製造 → ロットQRラベル貼付 → 甲へ納品
                                 ↓
[甲]  ① 入荷登録（ロットQRスキャン＋数量入力）
        → 在庫（ロット番号＋残数）として登録
                                 ↓
      ② 在庫確認・引当（有効期限が近い順に先入れ先出し）
                                 ↓
      ③ 出荷登録（出荷先・受注数量を指定してロットを引当）
        → 残数を減算、出荷履歴を記録
        → トレーサビリティQR を発行・印刷して製品に貼付
                                 ↓
[施工会社] 受領 → 現場で使用
                                 ↓
[甲]  ④ トレース照会（問い合わせ対応）
      ⑤ 有効期限監視 → 期限接近時に注意喚起メールを手動送信
      ⑥ 使用数の記録（施工会社からの報告に基づき更新）
```

### 5.2 業務要件

| No    | 業務要件                                | 内容                                                                                |
| ----- | --------------------------------------- | ----------------------------------------------------------------------------------- |
| BR-01 | 入荷はロット単位で登録する              | 段ボール1箱に貼付された1枚のロットQR をスキャンし、内包する本数を数量として入力する |
| BR-02 | 分納に対応する                          | 同一ロットが複数回に分けて納品された場合、数量を加算登録できる                      |
| BR-03 | 在庫は数量で管理する                    | 缶1本ごとの個体識別は行わず、ロット番号と残数で管理する                             |
| BR-04 | 先入れ先出しを支援する                  | 在庫一覧は有効期限が近い順に表示し、期限接近を色で警告する                          |
| BR-05 | 出荷はロットから引き当てる              | 受注数量分をロットの残数から減算する。残数が不足する場合は登録を拒否する            |
| BR-06 | 出荷ごとにトレーサビリティQR を発行する | 出荷1件につき1つの TraceNo を採番し、QR を発行する                                  |
| BR-07 | 出荷実績を照会できる                    | ロット番号または TraceNo から、出荷先・出荷日・数量・有効期限を照会できる           |
| BR-08 | 有効期限を監視する                      | 出荷済み製品のうち、有効期限まで30日以内のものを一覧表示する                        |
| BR-09 | 期限接近を通知する                      | 施工会社ごとに、対象製品を記載した注意喚起メールを手動で送信できる                  |
| BR-10 | 使用実績を記録する                      | 施工会社から報告された使用数を出荷履歴に記録し、未使用分のみを監視対象とする        |
| BR-11 | 納入先を管理する                        | 施工会社の会社名・メールアドレスを登録・変更・削除できる                            |

### 6.2 機能要件詳細

#### FR-01 入荷登録

| 項目       | 内容                                                                               |
| ---------- | ---------------------------------------------------------------------------------- |
| 目的       | 製造元から納品されたロットを在庫として登録する                                     |
| 入力       | ロットQR（スキャン）、有効期限、数量（1〜100,000）                                 |
| 主処理     | スキャン済みロットが既存であれば数量を加算、未登録であれば新規ロットとして登録する |
| ロット番号 | QR 未スキャン時は当日通番で自動採番する（`LOT-YYYYMMDD-NNNN`）                     |
| 出力       | 在庫（`quantity_total` / `quantity_remaining` の増加）、入荷日の記録               |
| 例外       | 出荷済み（残数0）ロットへの再入荷は、警告を表示したうえで在庫に戻す                |
| 要求水準   | QR を読み取れない場合でも、手動で入荷処理へ進めること                              |

#### FR-02 在庫一覧

| 項目     | 内容                                                                 |
| -------- | -------------------------------------------------------------------- |
| 目的     | 未出荷在庫を把握し、引当対象を判断する                               |
| 表示対象 | 残数が1以上のロット                                                  |
| 表示順   | 有効期限の昇順 → ロット番号の昇順 → 残数の昇順                       |
| 表示項目 | ロット番号、残数、入荷総数、有効期限、入荷日、期限状況               |
| 期限状況 | 期限切れ（赤）／残り30日以内（黄）／それ以上（緑）／期限未設定（灰） |
| 要求水準 | ロット番号による検索、列見出しによる並べ替えができること             |

#### FR-03 出荷登録

| 項目     | 内容                                                                              |
| -------- | --------------------------------------------------------------------------------- |
| 目的     | 施工会社への出荷を記録し、在庫を引き当てる                                        |
| 入力     | 出荷先（施工会社、必須）、受注数量（必須）、客先注文番号（任意・50文字以内）      |
| 引当方法 | ①ロットQR をスキャンする方法、②在庫一覧から対象ロットを選択する方法の2通り        |
| 主処理   | ロット残数の減算、出荷履歴の登録、トレーサビリティQR の発行を**一括して実行**する |
| 出力     | 出荷履歴、TraceNo、トレーサビリティQR の印刷画面                                  |
| 例外     | 残数が受注数量に満たない場合はエラーとし、ロットをまたぐ自動分割は行わない        |
| 要求水準 | 出荷先未選択のままスキャンした場合は登録せずエラーを表示すること                  |

#### FR-04 出荷リスト

| 項目     | 内容                                                                                       |
| -------- | ------------------------------------------------------------------------------------------ |
| 目的     | 出荷実績を確認し、施工会社での使用実績を記録する                                           |
| 表示順   | 出荷日の降順 → 登録日時の降順                                                              |
| 表示項目 | 出荷日、ロット番号、トレースNo、得意先No、出荷先、客先注文番号、出荷数量、使用数、期限状況 |
| 更新機能 | 使用数を 0 〜 出荷数量の範囲で更新できる                                                   |
| 絞込     | 出荷先（施工会社）による絞り込み                                                           |
| 要求水準 | 出荷数量と使用数が一致する行は、期限管理対象外として扱うこと                               |

#### FR-05 トレーサビリティ検索

| 項目     | 内容                                                                                 |
| -------- | ------------------------------------------------------------------------------------ |
| 目的     | 問い合わせに対し、製品の流通履歴を即座に回答する                                     |
| 入力     | ロット番号または TraceNo（手入力または QR スキャン）                                 |
| 出力     | ロットの現在状態（残数・有効期限・入荷日）、出荷履歴（出荷先・出荷日・数量・担当者） |
| 検索方式 | ロット番号で検索し、該当しない場合は TraceNo として再検索する                        |
| 要求水準 | 該当なしの場合は明示的に「製品が見つかりません」と表示すること                       |

#### FR-06 有効期限監視・アラート

| 項目         | 内容                                                                                          |
| ------------ | --------------------------------------------------------------------------------------------- |
| 目的         | 出荷済み製品の期限切れを未然に防ぐ                                                            |
| 監視対象     | トレーサビリティQR 発行分のうち、有効期限が **本日から30日以内**（日本時間基準）のもの        |
| 除外条件     | 未使用数量（出荷数量 − 使用数）が 0 のもの                                                    |
| 表示         | 施工会社別にグループ化し、TraceNo・ロット番号・数量・有効期限・残り日数・処理ステータスを表示 |
| 通知方式     | 担当者が施工会社ごとに「アラート送信」ボタンを押す **手動送信**                               |
| 送信対象     | 処理ステータスが「未使用」のもののみ                                                          |
| 送信不可条件 | 施工会社にメールアドレスが未登録の場合は送信ボタンを無効化する                                |
| 履歴         | 送信日時・送信先・対象 TraceNo・成否を記録し、直近50件を表示する                              |
| 要求水準     | 自動送信は行わない。担当者が定期的に画面を確認する運用とする                                  |

#### FR-07 納入先登録

| 項目 | 内容                                                                          |
| ---- | ----------------------------------------------------------------------------- |
| 目的 | 出荷先およびアラート送信先のマスタを保守する                                  |
| 入力 | 会社名（必須・100文字以内）、メールアドレス（任意・255文字以内）              |
| 採番 | 登録時にテナント内で一意の出荷先No（`company_no`）を自動採番する              |
| 操作 | 新規登録、編集、削除                                                          |
| 制約 | 出荷履歴またはトレーサビリティQR 発行履歴から参照されている会社は削除できない |

#### FR-08 製品情報公開ページ

| 項目     | 内容                                                                                |
| -------- | ----------------------------------------------------------------------------------- |
| 目的     | 施工会社・現場作業者が製品の正規性と有効期限を確認できるようにする                  |
| アクセス | トレーサビリティQR をスマートフォンの標準カメラで読み取る（**ログイン不要**）       |
| 表示項目 | ロット番号、施工先No、トレースNo、有効期限、販売元                                  |
| 要求水準 | 表示内容は URL に埋め込まず、サーバー側でデータベースから取得すること（改ざん防止） |

| NFR-A-03 | 同時実行制御     | 同一ロットへの同時操作時に、行ロックにより数量の更新欠落を防止する                                |
| NFR-A-04 | バックアップ     | データベース基盤（Supabase）の自動バックアップに準拠する                                          |

### 7.3 セキュリティ要件

| No       | 項目         | 要求水準                                                                                                 |
| -------- | ------------ | -------------------------------------------------------------------------------------------------------- |
| NFR-S-01 | 認証         | 全機能（公開ページを除く）はログイン必須とする                                                           |
| NFR-S-02 | テナント分離 | データベースの行単位セキュリティ（RLS）により、他社データへ一切アクセスできないこと                      |
| NFR-S-03 | 通信の暗号化 | 全通信を HTTPS とする                                                                                    |
| NFR-S-04 | 入力検証     | サーバー側で全入力値をスキーマ検証する                                                                   |
| NFR-S-05 | 公開ページ   | 認証不要で公開する情報は、製品識別に必要な最小限（ロット番号・施工先No・トレースNo・有効期限）に限定する |

> セキュリティ要件の詳細は別冊「セキュリティ要件書（MYOU-SEC-001）」に定義する。

## 8. 制約事項・前提条件

| No    | 区分 | 内容                                                                                                                |
| ----- | ---- | ------------------------------------------------------------------------------------------------------------------- |
| CN-01 | 前提 | 本システムは HR-DX SaaS のマルチテナント基盤上で、甲専用テナントとして提供される                                    |
| CN-02 | 前提 | 出荷登録および有効期限アラートの利用前に、施工会社（納入先）マスタの登録が完了していること                          |
| CN-03 | 前提 | ロットQR ラベルは、甲が定めた書式（`LOT:…,MFG:…,EXP:…`）で製造会社側にて貼付されること                              |
| CN-04 | 制約 | QR スキャンにはカメラ搭載端末とカメラ使用許可が必要である                                                           |
| CN-05 | 制約 | 缶1本ごとの個体識別は行わない（ロット番号＋数量による管理とする）                                                   |
| CN-06 | 制約 | 出荷時に受注数量がロット残数を超える場合、複数ロットへの自動分割は行わない                                          |
| CN-07 | 制約 | トレーサビリティQR は出荷1件につき1種類。缶ごとに内容の異なる QR は発行しない（同一 QR を必要部数だけ複製印刷する） |
| CN-08 | 制約 | メール送信には SMTP サーバーの設定が必要である                                                                      |

## 9. スコープ外事項

以下は本フェーズの提供範囲に含まない。導入提案時に言及された事項を含むため、明示的に記載する。

| No    | 事項                                     | 理由・現行の代替運用                                                                                               |
| ----- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| OS-01 | 有効期限アラートの**自動メール送信**     | 本フェーズでは手動送信のみ提供する。担当者が定期的に監視画面を確認し、「アラート送信」ボタンから通知する運用とする |
| OS-02 | 購買管理システムとのデータ連携           | 連携先の仕様が未確定のため、別途計画とする                                                                         |
| OS-03 | 売掛管理システムとのデータ連携           | 同上                                                                                                               |
| OS-04 | 缶1本ごとの個体シリアル管理              | 業務実態（段ボール単位の入出庫）に合わないため、ロット＋数量管理を採用した                                         |
| OS-05 | 施工会社による本システムへの直接ログイン | 施工会社はアラートメールの受信と公開ページの閲覧のみとする                                                         |
| OS-06 | 製造会社によるロットQR のシステム発行    | ラベルは甲が定めた書式に従い製造会社側で用意する                                                                   |

## 10. 受入基準

以下をすべて満たすことをもって、本システムの検収完了とする。

| No    | 受入項目                   | 判定基準                                                                                             |
| ----- | -------------------------- | ---------------------------------------------------------------------------------------------------- |
| AC-01 | 入荷登録                   | ロットQR をスキャンし数量を入力すると、在庫一覧に該当ロットが残数付きで表示される                    |
| AC-02 | 分納の加算                 | 同一ロットを再度入荷登録すると、残数・入荷総数が加算され、警告メッセージが表示される                 |
| AC-03 | 在庫の並び順               | 在庫一覧が有効期限の近い順に表示され、30日以内の在庫が黄色で警告表示される                           |
| AC-04 | 出荷登録（QR）             | 出荷先・数量を指定してロットQR をスキャンすると、残数が減算され、トレーサビリティQR の印刷画面が開く |
| AC-05 | 出荷登録（在庫表）         | 在庫一覧から対象ロットを選択して出荷でき、AC-04 と同一の結果が得られる                               |
| AC-06 | 残数不足の拒否             | 受注数量が残数を超える場合、登録されずエラーメッセージが表示される                                   |
| AC-07 | 出荷先未選択の拒否         | 出荷先を選択せずにスキャンした場合、登録されずエラーメッセージが表示される                           |
| AC-08 | 出荷リスト                 | 出荷実績が出荷日の新しい順に表示され、出荷先で絞り込める                                             |
| AC-09 | 使用数の更新               | 使用数を 0〜出荷数量の範囲で更新でき、範囲外の値は拒否される                                         |
| AC-10 | トレース照会（ロット番号） | ロット番号を入力すると、有効期限・入荷日・出荷履歴が表示される                                       |
| AC-11 | トレース照会（TraceNo）    | TraceNo を入力またはスキャンすると、AC-10 と同一のロット情報が表示される                             |
| AC-12 | 有効期限監視               | 有効期限30日以内の出荷済み製品が施工会社別に一覧表示される                                           |
| AC-13 | アラート送信               | 「アラート送信」ボタンにより該当施工会社へメールが送信され、送信履歴に記録される                     |
| AC-14 | アラート送信の制限         | メールアドレス未登録の施工会社では送信ボタンが無効となる                                             |
| AC-15 | 納入先マスタ               | 施工会社を登録・編集・削除でき、出荷実績のある会社は削除できない                                     |
| AC-16 | 公開ページ                 | トレーサビリティQR をスマートフォンで読み取ると、ログインなしで製品情報ページが表示される            |
| AC-17 | テナント分離               | 他テナントのデータが一切表示されない                                                                 |
| AC-18 | 認証                       | 未ログイン状態で各画面へアクセスすると、ログイン画面へ遷移する                                       |
