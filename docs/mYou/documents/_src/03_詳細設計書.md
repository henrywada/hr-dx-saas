## 1. はじめに

### 1.1 本書の目的

本書は、基本設計書（MYOU-BD-001）で定義した方式に基づき、実装レベルの仕様（モジュール構成、テーブル定義、処理仕様、メッセージ、制限値）を定義したものである。保守・改修の際の一次資料として使用する。

### 1.2 表記規則

| 表記           | 意味                                           |
| -------------- | ---------------------------------------------- |
| `モノスペース` | ファイル名、関数名、テーブル名、列名、コード値 |
| 型「文字列」   | PostgreSQL の `text` 型                        |
| 型「日付」     | PostgreSQL の `date` 型                        |
| 型「日時」     | PostgreSQL の `timestamptz` 型                 |

## 4. データベース関数（RPC）詳細設計

在庫数量を変更する処理は、複数テーブルへの更新を伴い、かつ同時実行時の不整合が業務影響に直結するため、データベース関数として実装し、行ロックを取得したうえで単一トランザクションで実行する。

いずれの関数も `SECURITY INVOKER`（呼び出し利用者の権限で実行）とし、RLS によるテナント分離を維持する。

### 4.1 myou_receive_lot（入荷登録）

**シグネチャ**

```
myou_receive_lot(
    p_lot_no          text,   -- ロット番号
    p_qr_payload      text,   -- ロットQR の内容
    p_expiration_date date,   -- 有効期限
    p_quantity        integer,-- 入荷数量
    p_received_at     date    -- 入荷日
) RETURNS TABLE (lot_id uuid, is_new boolean, previous_status text)
```

**処理**

| 順  | 処理内容                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 自テナント内の `lot_no` 一致行を `FOR UPDATE` で検索し、行ロックを取得する                                                                                                                              |
| 2   | 該当なしの場合：新規ロットを登録する（`quantity_total` = `quantity_remaining` = 入荷数量、`status` = `in_stock`）。戻り値 `is_new` = true                                                               |
| 3   | 該当ありの場合：`quantity_total` と `quantity_remaining` に入荷数量を加算し、有効期限・入荷日を更新、`status` を `in_stock` に設定する。戻り値 `is_new` = false、`previous_status` に更新前の状態を返す |

**設計意図**：同一ロットへ同時に入荷登録が行われた際、行ロックがないと後勝ちで加算が失われる（lost update）。`FOR UPDATE` により直列化する。

### 4.2 myou_deliver_from_lot（出荷登録）

**シグネチャ**

```
myou_deliver_from_lot(
    p_lot_no            text,
    p_company_id        uuid,
    p_quantity          integer,
    p_delivered_by      text,
    p_delivery_date     date,
    p_trace_no          text,
    p_customer_order_no text DEFAULT NULL,
    p_trace_label_id    uuid DEFAULT NULL
) RETURNS TABLE (lot_id uuid, expiration_date date)
```

**処理**

| 順  | 処理内容                                                                                              | 異常時                                       |
| --- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| 1   | 自テナント内の `lot_no` 一致行を `FOR UPDATE` で検索                                                  | 該当なし：`ロット % が見つかりません`        |
| 2   | 残数と出荷数量を比較                                                                                  | 不足：`在庫数量が不足しています（残り%個）`  |
| 3   | `p_company_id` が自テナントの施工会社か検証                                                           | 不一致：`出荷先（施工会社）が見つかりません` |
| 4   | `quantity_remaining` を減算。0 になった場合は `status` を `depleted` に、それ以外は `in_stock` に更新 | —                                            |
| 5   | `myou_delivery_logs` に出荷履歴を登録（客先注文番号・TraceNo を含む）                                 | —                                            |
| 6   | `myou_trace_labels` にトレーサビリティQR 発行を登録                                                   | —                                            |
| 7   | ロットID と有効期限を返す                                                                             | —                                            |

**設計意図**

- 手順 4〜6 を同一トランザクションで実行することにより、「在庫は減ったが履歴が残っていない」といった部分的な反映を防ぐ
- 手順 3 のテナント検証は、本関数が `SECURITY INVOKER` で直接呼び出し可能であることを踏まえ、テナントを越えた出荷登録を防ぐために設けている
- 残数不足時にロットをまたぐ自動引当は行わない。業務上、どのロットから払い出したかが追跡上重要なため、別ロットの再スキャンを利用者に促す

## 5. サーバー処理詳細設計

### 5.1 共通事項

| 項目       | 仕様                                                                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 認証確認   | 全ての読み取り・更新処理の冒頭で `getServerUser()` を呼び、`tenant_id` を取得できない場合は処理を中断する（更新処理は `{ success: false, error: '認証エラー' }` を返す） |
| 入力検証   | 更新処理は Zod スキーマで検証し、最初のエラーメッセージを返す                                                                                                            |
| 絞り込み   | 全てのクエリに `tenant_id` 条件を明示的に付与する（RLS と併せた二重防御）                                                                                                |
| 再描画     | 更新成功後、関連画面のキャッシュを無効化する（`revalidatePath`）                                                                                                         |
| エラー処理 | データベースエラーはサーバー側ログへ詳細を出力し、利用者へは定型メッセージのみ返す                                                                                       |

### 5.2 入力検証スキーマ

| スキーマ               | 対象           | 検証内容                                                                                                         |
| ---------------------- | -------------- | ---------------------------------------------------------------------------------------------------------------- |
| `receiveLotSchema`     | 入荷登録       | `expiration_date`：`YYYY-MM-DD` 形式かつ実在する日付／`quantity`：1以上100,000以下の整数／`scanned_lot_no`：任意 |
| `deliverFromLotSchema` | 出荷登録       | `lot_no`：1文字以上／`company_id`：UUID 形式／`quantity`：1以上の整数／`customer_order_no`：50文字以内（任意）   |
| `upsertCompanySchema`  | 施工会社       | `name`：1〜100文字／`email_address`：255文字以内かつメール形式（空文字は未登録として許容）                       |
| `companyIdSchema`      | 会社ID         | UUID 形式                                                                                                        |
| `processStatusSchema`  | 処理ステータス | `unused` / `used` / `alert_ignored` のいずれか                                                                   |

### 5.3 更新処理（Server Actions）

#### receiveLot（入荷登録）

| 項目       | 内容                                                                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 入力       | `{ scanned_lot_no?, expiration_date, quantity }`                                                                                    |
| 処理       | ①認証確認 ②入力検証 ③ロット番号の決定（スキャン値、または当日通番＋1で自動採番） ④`myou_receive_lot` 呼び出し ⑤画面キャッシュ無効化 |
| 自動採番   | 当日発行分（`LOT-YYYYMMDD-%`）を取得し、通番の最大値を **数値比較** で求めて＋1する                                                 |
| 戻り値     | `{ success, registered_lot_no?, warning?, error? }`                                                                                 |
| 警告条件   | 更新前 `depleted` → 再入荷警告／更新前 `in_stock` → 数量加算警告                                                                    |
| 無効化対象 | 入荷登録画面、在庫一覧画面                                                                                                          |

#### deliverFromLot（出荷登録）

| 項目              | 内容                                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 入力              | `{ lot_no, company_id, quantity, customer_order_no? }`                                                                                                                   |
| 処理              | ①認証確認 ②入力検証 ③施工会社の存在確認と出荷先No取得 ④TraceNo 採番 ⑤発行ID（UUID）の事前採番 ⑥`myou_deliver_from_lot` 呼び出し ⑦画面キャッシュ無効化 ⑧QR ペイロード生成 |
| 発行ID の事前採番 | QR に埋め込む公開ページ URL を組み立てるため、登録前にアプリケーション側で UUID を生成し、RPC へ引き渡す                                                                 |
| 基準 URL          | `NEXT_PUBLIC_APP_URL` → `VERCEL_URL` → `http://localhost:3000` の優先順で決定する                                                                                        |
| 戻り値            | `{ success, label?: { trace_no, lot_no, company_no, quantity, expiration_date, qr_payload }, error? }`                                                                   |
| 無効化対象        | 出荷登録画面、在庫一覧画面、出荷リスト画面                                                                                                                               |

#### sendManualAlert（アラート送信）

| 項目     | 内容                                                                                                                                                                                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入力     | `companyId`（UUID）                                                                                                                                                                                                                                        |
| 処理     | ①認証確認 ②会社ID検証 ③対象 QR 発行分の抽出（期限が本日〜30日後） ④出荷履歴から使用数を突合し未使用数量を算出 ⑤未使用数量が0の行を除外 ⑥処理ステータスが `unused` の行のみ抽出 ⑦送信先メールアドレス確認 ⑧メール送信 ⑨送信履歴の記録 ⑩画面キャッシュ無効化 |
| 戻り値   | `{ success }` または `{ success: false, error }`                                                                                                                                                                                                           |
| 履歴記録 | 送信成否にかかわらず記録する（失敗時は `status='error'` とエラー内容を保存）                                                                                                                                                                               |

#### updateTraceProcessStatus（処理ステータス更新）

| 項目           | 内容                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------- |
| 入力           | `labelId`（UUID）、`processStatus`                                                                |
| 処理           | ①認証確認 ②ID・ステータス検証 ③自テナント条件付きで更新 ④画面キャッシュ無効化                     |
| 画面上の選択肢 | 「未使用」「アラート無視」の2種類。「使用済」は出荷リストの使用数から判定するため直接選択させない |

#### updateDeliveryUsedQuantity（使用数更新）

| 項目       | 内容                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------- |
| 入力       | `logId`（UUID）、`usedQuantity`（整数）                                                                  |
| 処理       | ①認証確認 ②ID検証 ③0以上の整数か検証 ④対象出荷履歴の取得 ⑤出荷数量以下か検証 ⑥更新 ⑦画面キャッシュ無効化 |
| エラー     | 対象なし：`出荷履歴が見つかりません。`／範囲外：`使用数は出荷数量（N）以下にしてください。`              |
| 無効化対象 | 出荷リスト画面、有効期限監視画面                                                                         |

#### upsertCompany / deleteCompany（施工会社の保守）

| 項目           | 内容                                                                             |
| -------------- | -------------------------------------------------------------------------------- |
| 新規登録       | 自テナントの `company_no` 最大値＋1を採番して登録する                            |
| 更新           | `id` と `tenant_id` の両方を条件に更新する                                       |
| メールアドレス | 空文字は NULL（未登録）として保存する                                            |
| 削除           | `id` と `tenant_id` の両方を条件に削除する                                       |
| 削除不可       | 外部キー違反（エラーコード `23503`）を検出し、参照されている旨のメッセージを返す |

### 5.4 読み取り処理（Queries）

| 関数                       | 取得内容                       | 並び順                                   | 上限    |
| -------------------------- | ------------------------------ | ---------------------------------------- | ------- |
| `getCompanies()`           | 施工会社一覧                   | 会社名の昇順                             | —       |
| `getLots()`                | 残数1以上のロット              | 有効期限昇順 → ロット番号昇順 → 残数昇順 | 1,000件 |
| `getDeliveryLogs()`        | 出荷履歴（ロット・会社を結合） | 出荷日降順 → 登録日時降順                | 500件   |
| `getExpiringTraceLabels()` | 期限30日以内の QR 発行分       | 有効期限昇順                             | —       |
| `getAlertLogs()`           | アラート送信履歴               | 送信日時降順                             | 50件    |
| `getLotTrace(identifier)`  | ロット情報と出荷履歴           | 出荷日降順 → 登録日時降順                | —       |
| `getPublicTraceInfo(id)`   | 公開ページ用の製品情報         | —                                        | 1件     |

#### getLotTrace の検索仕様

| 順  | 処理                                                                                             |
| --- | ------------------------------------------------------------------------------------------------ |
| 1   | 入力値を `lot_no` として自テナント内を検索                                                       |
| 2   | 該当なしの場合、`trace_no` として `myou_trace_labels` を検索し、紐付く `lot_id` からロットを取得 |
| 3   | いずれも該当なしの場合は `null` を返す                                                           |
| 4   | ロットが特定できた場合、そのロットの出荷履歴（施工会社名を含む）を取得する                       |

#### getExpiringTraceLabels の抽出仕様

| 順  | 処理                                                                   |
| --- | ---------------------------------------------------------------------- |
| 1   | 有効期限が「本日（日本時間）」〜「30日後」の範囲にある QR 発行分を取得 |
| 2   | 同一 TraceNo の出荷履歴から使用数を取得して突合                        |
| 3   | 未使用数量 ＝ 出荷数量 − 使用数（下限0）を算出                         |
| 4   | 未使用数量が0の行を除外する                                            |

#### getPublicTraceInfo の特例

公開ページはログインを前提としないため、RLS を適用する通常の接続では取得できない。本関数のみ管理者用クライアント（RLS バイパス）を使用する。安全性は次の設計で担保する。

| 対策         | 内容                                                                       |
| ------------ | -------------------------------------------------------------------------- |
| 入力の厳格化 | 引数が UUID 形式に一致しない場合、データベースへ問い合わせず `null` を返す |
| 取得列の限定 | ロット番号・TraceNo・出荷先No・有効期限のみを取得する                      |
| 単一行の取得 | 主キー（`id`）による1件取得に限定し、一覧・検索を提供しない                |
| 推測困難性   | 発行ID は UUID v4 であり、総当たりによる列挙は現実的でない                 |

## 6. 共通ロジック詳細設計

### 6.1 QR 解析・採番（`lib/qr-parser.ts`）

| 関数                                        | 機能                                                                                            |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `parseLotQrContent(text)`                   | ロットQR を解析し、ロット番号・製造日・有効期限を返す。書式不一致時は全文をロット番号として扱う |
| `parseTraceQrContent(text)`                 | トレーサビリティQR を解析する。URL 形式（新書式）とキー・値形式（旧書式）の両方に対応           |
| `extractSearchIdentifier(text)`             | 検索用の識別子を取り出す。TraceNo を優先し、無ければロット番号を返す                            |
| `buildLotQrPayload(lotNo, mfg, exp)`        | ロットQR の文字列を組み立てる                                                                   |
| `buildLotNo(dateYmd, sequence)`             | `LOT-YYYYMMDD-NNNN` を組み立てる                                                                |
| `getMaxLotSequence(lotNos, dateYmd)`        | 当日発行済みロット番号から最大通番を求める                                                      |
| `buildTraceNo(dateYmd, sequence)`           | `YYYYMMDD-NNNN` を組み立てる                                                                    |
| `getMaxTraceSequence(traceNos, dateYmd)`    | 当日発行済み TraceNo から最大通番を求める                                                       |
| `buildTraceQrPayload(baseUrl, id, traceNo)` | 公開ページ URL を組み立てる                                                                     |

> 通番の最大値は、文字列の辞書順では5桁以上（10000〜）で大小関係を誤るため、必ず数値へ変換して比較する。

### 6.2 有効期限計算（`lib/expiration.ts`）

| 関数                                           | 仕様                                                                                  |
| ---------------------------------------------- | ------------------------------------------------------------------------------------- |
| `getDaysUntilExpiration(expirationDate, now?)` | 有効期限までの残日数を返す。期限当日は `0`、期限切れは負数、未設定・不正日付は `null` |

**日本時間基準の計算**：日付文字列を必ず `YYYY-MM-DDT00:00:00+09:00` として解釈し、「日本時間の本日0時」との差分を暦日で求める。UTC 解釈とローカル解釈が混在すると残日数が±1日ずれるため、明示的にタイムゾーンを指定している。

**画面表示への反映**

| 残日数 | 表示       | 色  |
| ------ | ---------- | --- |
| `null` | 期限未設定 | 灰  |
| 0以下  | 期限切れ   | 赤  |
| 1〜30  | 残りN日    | 黄  |
| 31以上 | 残りN日    | 緑  |

### 6.3 処理ステータス（`lib/process-status.ts`）

| 関数・定数                   | 仕様                                             |
| ---------------------------- | ------------------------------------------------ |
| `PROCESS_STATUS_VALUES`      | `['unused','used','alert_ignored']`              |
| `PROCESS_STATUS_EDIT_VALUES` | 画面で選択可能な値：`['unused','alert_ignored']` |
| `processStatusLabel(status)` | 表示名を返す（未使用／使用済／アラート無視）     |
| `filterUnusedForAlert(rows)` | アラート送信対象（`unused`）のみを抽出する       |

## 9. エラーハンドリング設計

### 9.1 方針

| No    | 方針                                                                                       |
| ----- | ------------------------------------------------------------------------------------------ |
| EH-01 | 利用者へ返すメッセージには、内部構造・SQL・スタックトレースを含めない                      |
| EH-02 | 原因究明に必要な詳細（エラーコード、ヒント）はサーバー側ログにのみ出力する                 |
| EH-03 | 業務上の判断が必要な事象（重複入荷、再入荷など）は、エラーではなく警告として処理を継続する |
| EH-04 | 照会処理の失敗は画面遷移させず、検索条件を保持したままエラーバナーを表示する               |
| EH-05 | 読み取り処理でエラーが発生した場合は空配列を返し、画面全体の停止を避ける                   |

| 区分               | 表示                         | 例                                   |

| `NEXT_PUBLIC_APP_URL`                                 | トレーサビリティQR に埋め込む基準 URL      | 推奨                 |
| `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` | メール送信設定                             | アラート利用時は必須 |
| `MAIL_FROM`                                           | 送信元アドレス                             | 任意                 |

> `SUPABASE_SERVICE_ROLE_KEY` はデータベースのアクセス制御を迂回できる資格情報である。サーバー側のみで使用し、ブラウザへ露出させてはならない。
